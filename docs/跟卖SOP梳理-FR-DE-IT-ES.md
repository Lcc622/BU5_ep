# BU5-跟卖 SOP 梳理（FR / DE / IT / ES 通用）

> 来源：kdocs.cn 文档，作者：TERESA
> 整理日期：2026-03-18

---

## 一、目标（Goal）

和 UK 一样，核心目标是：

- 新老版本同时存在购物车
- 新版本价格高于老版本 €0.1，老版本优先出单
- 用真实销售测试退货率变化
- 降低人工制表错误
- 实现半自动化批量生成上传模板

---

## 二、整体流程结构

```
输入新版本 SKU
↓
匹配老版本 SKU
↓
抓取老版本 ASIN
↓
生成跟卖上新表
↓
人工复核
↓
上传 Amazon
```

---

## 三、详细操作步骤

### Step 1：输入触发

**目标**：确认需要跟卖的新版本 SKU

**后缀规范（⚠️ 与 UK 不同，重点看这里）**：

| 情况 | 处理方式 |
|------|---------|
| 无尾缀的 SKU | 保持无尾缀，生成的新款也无尾缀 |
| 带 `-CO` 尾缀的 SKU | 新款同样生成 `-CO` 尾缀 |

> UK 是统一归一化为 `-UK1`；FR/DE/IT/ES 没有统一国家后缀，按原样保留。

**操作**：
- 输入：新版本 SKU（支持批量）
- 精确到 SKU 级别（不是 style）

---

### Step 2：匹配老版本 SKU

**目标**：找到新版本对应的老版本 SKU

**逻辑**：
- 系统根据新版本 SKU
- 在 BI 入库更新表中匹配老版本 SKU

**输出**：
- 新版本 SKU
- 对应老版本 SKU

> 若 BI 无法稳定匹配，可使用人工维护的新老 SKU 对照表。

---

### Step 3：抓取老版本 ASIN

**目标**：获取老版本对应的 ASIN

**逻辑**：
- 根据老版本 SKU
- 调用 Amazon 后台 Only Thing Report 或内部接口
- 抓取老版本 ASIN

**输出**：
- 老版本 ASIN

---

### Step 4：生成跟卖上新表（字段规则最终版）

#### 必须修改字段清单（9 个强制更新字段）

| # | 字段名 | 字段 key | 规则 |
|---|--------|---------|------|
| 1 | `item SKU` | `item_sku` | 填新版本 SKU；不可为空；必须唯一 |
| 2 | `product ID` | `external_product_id` | 填老版本 ASIN；用于跟卖挂靠 |
| 3 | `product ID type` | `external_product_id_type` | 批量填写：`ASIN`；所有行必须一致 |
| 4 | `model style number` | `model_style_number` | 填新版本 SKU |
| 5 | `part number` | `part_number` | 填新版本 SKU；与 model_style_number 保持一致 |
| 6 | `price (standard price)` | `standard_price` | 新版本价格 = 老版本价格 + 0.1；保留两位小数 |
| 7 | `list price` | `list_price` | list_price = (老版本价格 + 0.1) + 10；保留两位小数 |
| 8 | `quantity` | `quantity` | 批量填写：`2` |
| 9 | `image（所有图片列）` | `main_image_url` 及所有 image 列 | **全部清空**；跟卖不需要重新上传图片，避免触发图片审核 |

#### 其他字段不变（全部沿用老版本）

包括但不限于：标题、五点、描述、类目、变体结构、品牌、尺码属性、颜色属性、材质属性

---

## 五、最终字段计算逻辑汇总（给开发）

```
new_price = old_price + 0.1
list_price = new_price + 10

quantity = 2
image = null
product_id_type = ASIN
```

---

## 六、人工复核清单（上传前）

上传前必须确认：

- [ ] SKU 是否正确
- [ ] ASIN 是否匹配
- [ ] price 是否 +0.1
- [ ] list_price 是否 +10
- [ ] quantity 是否为 2
- [ ] image 是否清空

确认无误后上传 Amazon。

---

## ⚠️ 现存问题（关键坑位）

### 问题

BI 上新排查界面只显示**已入库的部分 SKU**，但实际业务要求是：

> 只要一个 SKC（颜色）开始入库，该颜色下**所有 SKU（所有尺码）都必须安排跟卖上新**。

**风险**：
- 可能只入库 2 个 SKU，但该颜色共有 8 个 SKU
- 如果只按 BI 显示的 2 个做跟卖 → 同色断码、变体结构异常

### 解决方式（新增必要步骤）

**必须按照原有老版本有的全部 SKU，完成所有 SKU 的跟卖上新**，确保：
- 不漏尺码
- 不漏 SKU
- 不破坏变体结构

## 与 UK 的核心差异对比

| 对比项 | UK | FR / DE / IT / ES |
|--------|----|--------------------|
| 后缀规范 | `-UK1+` 统一归一化为 `-UK1` | 无尾缀保持无尾缀；`-CO` 尾缀保持 `-CO` |
| 货币 | GBP | EUR |
| 字段规则 | 相同 | 相同 |
| 价格计算 | +0.1 / +10 | +0.1 / +10（EUR） |
| 图片处理 | 全部清空 | 全部清空 |
| 不漏尺码要求 | 相同 | 相同 |
